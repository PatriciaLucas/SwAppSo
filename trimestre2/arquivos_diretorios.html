Arquivos, Sistemas de Arquivos e Diretórios

Conceitos fundamentais, com comparação entre Windows e Linux

1. O conceito de arquivo

Desde os primórdios da computação, existe a necessidade de armazenar informações para uso posterior, como programas e dados. Boa parte do uso de um computador consiste em recuperar e apresentar informações previamente armazenadas: documentos, fotografias, músicas e vídeos. O próprio sistema operacional também precisa manter informações armazenadas, como programas, bibliotecas e arquivos de configuração. Para organizar esse armazenamento surgiu o conceito de arquivo.

Definição Um arquivo é uma sequência de bytes armazenada em um dispositivo físico não volátil (como um SSD ou HD), que preserva seu conteúdo mesmo quando o computador é desligado. Cada arquivo possui um nome que permite sua localização e acesso.

Do ponto de vista do usuário e das aplicações, o arquivo é a unidade básica de armazenamento persistente de informação. Arquivos são extremamente versáteis: podem conter desde um texto com poucos caracteres até vídeos com dezenas de gigabytes.

Como um dispositivo de armazenamento pode conter milhões de arquivos, eles são organizados em estruturas hierárquicas chamadas diretórios (ou pastas), o que facilita a localização e o acesso pelos usuários. A figura a seguir ilustra essa organização.

A organização do conteúdo de arquivos e diretórios dentro de um dispositivo físico é chamada de sistema de arquivos. Existem vários sistemas de arquivos: NTFS (Windows), Ext2/Ext3/Ext4 (Linux), HFS/APFS (macOS) e FAT (usado em pendrives, câmeras e players MP3).

Um dispositivo físico é estruturado em um ou mais volumes (ou partições); cada volume pode armazenar um sistema de arquivos próprio. Assim, um mesmo disco pode conter volumes com sistemas de arquivos diferentes, como FAT, NTFS ou Ext4.

2. Atributos e operações sobre arquivos

Além do conteúdo, um arquivo é caracterizado por atributos (ou metadados) — informações adicionais sobre o arquivo — e por operações que podem ser realizadas sobre ele.

Atributos mais comuns

AtributoDescrição
NomeString que identifica o arquivo para o usuário: "foto1.jpg", "documento.pdf".
TipoFormato dos dados (texto, imagem, vídeo). Muitas vezes indicado pela extensão do nome.
TamanhoTamanho do conteúdo, geralmente em bytes.
DatasDatas de criação, último acesso e última modificação.
ProprietárioEm sistemas multiusuário, cada arquivo tem um dono.
Permissões de acessoQuais usuários podem ler, escrever ou remover o arquivo.
LocalizaçãoDispositivo e posição onde o arquivo está armazenado.

Operações básicas

O acesso aos arquivos é feito por meio de chamadas de sistema e funções de bibliotecas. As operações básicas são:

  • Criar — aloca espaço no dispositivo e define os atributos iniciais do arquivo;
  • Abrir — solicita ao sistema operacional acesso ao arquivo antes de ler/escrever;
  • Ler — transfere dados do arquivo para a memória da aplicação;
  • Escrever — transfere dados da aplicação para o arquivo;
  • Fechar — informa ao sistema que o arquivo não é mais necessário;
  • Remover — elimina o arquivo, liberando o espaço ocupado;
  • Alterar atributos — modifica nome, permissões, datas, etc.
Exemplo Copiar um arquivo A para um novo arquivo B envolve várias operações básicas em sequência: abrir A, criar e abrir B, ler o conteúdo de A e escrever em B, e por fim fechar A e B.

3. Formatos e identificação de arquivos

Na forma mais simples, um arquivo contém uma sequência de bytes que pode representar textos, imagens, vídeos ou código executável. O núcleo do sistema operacional geralmente reconhece poucos formatos (como executáveis); os demais são vistos apenas como sequências de bytes, cabendo às aplicações interpretá-los.

Um problema importante é: como reconhecer o tipo de conteúdo de um arquivo? Existem três abordagens principais:

  • Extensão do nome — a forma mais usada: "praia.jpg", "musica.mp3". Introduzida pelo DOS nos anos 1980, com o padrão "8.3" (8 caracteres de nome + 3 de extensão).
  • Números mágicos (magic numbers) — bytes no início do conteúdo que identificam o tipo, independentemente do nome. Usados pelo comando file em sistemas UNIX.
  • Tipos MIME — padrão "tipo/subtipo" usado para identificar arquivos transferidos por e-mail ou na Web, como text/html ou image/png.

Observação Arquivos de texto também variam entre sistemas: no Linux/UNIX, as linhas terminam com o caractere New Line (\n); no Windows, terminam com Carriage Return + New Line (\r\n). Essa diferença pode causar problemas ao transferir arquivos de texto entre os dois sistemas.

4. Sistemas de arquivos

Um sistema de arquivos é o subsistema do sistema operacional responsável por implementar o conceito de arquivo sobre o armazenamento bruto oferecido pelo hardware. Ele resolve problemas que vão do acesso físico ao disco até a interface de alto nível usada pelos programadores.

De forma simplificada, a implementação de um sistema de arquivos é organizada em camadas:

  • Aplicação — solicita operações de leitura, escrita e remoção de arquivos;
  • Sistema de arquivos lógico — gerencia metadados, nomes de arquivos, diretórios e permissões de acesso;
  • Sistema de arquivos virtual (VFS) — camada que permite que diferentes sistemas de arquivos (NTFS, Ext4, FAT...) sejam acessados por uma interface única;
  • Sistema de arquivos físico — realiza a gravação efetiva dos blocos de dados no disco.

Essa camada de abstração (o VFS) é o que permite, por exemplo, que um mesmo sistema operacional acesse simultaneamente um disco formatado em NTFS, um pendrive em FAT32 e uma pasta compartilhada pela rede — tudo através das mesmas operações de abrir, ler e escrever arquivos.

5. Volumes, partições e montagem: Windows x Linux

Um disco é dividido em uma pequena área reservada (com a tabela de partições e o código de inicialização do sistema) e uma ou mais partições. Cada partição pode ser formatada de forma independente, recebendo um sistema de arquivos próprio. O termo volume é usado para designar um espaço de armazenamento de dados do ponto de vista do sistema operacional; na forma mais simples, cada volume corresponde a uma partição.

Antes de ser usado, todo volume precisa ser montado: o sistema operacional lê as informações do volume e cria as estruturas necessárias para que os processos possam acessar seus arquivos. É aqui que Windows e Linux adotam abordagens visivelmente diferentes.

AspectoWindowsLinux
Identificação de volumeLetra de unidade: C:\, D:\, E:\...Ponto de montagem dentro da árvore: /, /home, /media/usb
Separador de caminhoBarra invertida \Barra /
Sistema de arquivos padrãoNTFSExt4 (mais comum)
Pendrive/CD-ROMNova letra de unidade (ex: E:\)Montado em /media ou /mnt
Observação Apesar da abordagem tradicional por letras de unidade, o próprio NTFS também suporta a montagem de volumes como subdiretórios de uma árvore, de forma semelhante ao Linux — recurso pouco usado por usuários comuns, mas disponível no Windows.

6. Diretórios

Um diretório (também chamado de pasta ou folder) é um contêiner de arquivos e de outros diretórios. Assim como os arquivos, diretórios possuem nome e atributos. Todo sistema de arquivos tem um diretório raiz (root directory), a partir do qual toda a árvore de diretórios se organiza.

Do ponto de vista de implementação, um diretório é, na prática, um arquivo especial cujo conteúdo é uma tabela de entradas: cada entrada aponta para um arquivo, um subdiretório ou um atalho. Ou seja, um diretório não contém fisicamente os arquivos — ele apenas os relaciona.

No Linux, a estrutura de diretórios segue um padrão chamado FHS (Filesystem Hierarchy Standard), com diretórios de papel bem definido logo abaixo da raiz:

DiretórioFunção
/bin, /sbinProgramas executáveis essenciais do sistema.
/etcArquivos de configuração do sistema.
/homeDiretórios pessoais dos usuários (equivalente a C:\Users no Windows).
/devArquivos que representam dispositivos de hardware.
/varDados variáveis: logs, filas de impressão, caches.
/media, /mntPontos de montagem de mídias removíveis e volumes externos.

No Windows, embora exista uma organização similar por convenção — como C:\Windows, C:\Program Files e C:\Users — não há um padrão tão rigidamente definido quanto o FHS do Linux.

A maioria dos sistemas operacionais também define, para cada processo em execução, um diretório de trabalho (working directory): o local usado por padrão para criar ou abrir arquivos, quando o caminho completo não é informado.

7. Caminhos de acesso

Como os arquivos estão espalhados pela hierarquia de diretórios, é preciso conhecer sua localização completa — não apenas seu nome — para poder abri-los. Essa localização é chamada de caminho de acesso (path).

O caractere separador de nomes no caminho depende do sistema: o Windows usa \, enquanto sistemas UNIX/Linux usam /. Assim, o mesmo arquivo poderia ser representado como:

  • Windows: C:\Users\Maziero\public_html\index.html
  • Linux: /home/maziero/public_html/index.html

Existem duas formas principais de indicar um caminho:

  • Caminho absoluto — parte sempre do diretório raiz. Ex: /usr/local/share/fortunes/brasil.dat ou C:\Windows\System32.
  • Caminho relativo — parte do diretório de trabalho atual, podendo usar elementos especiais: . (o próprio diretório) e .. (o diretório pai). Ex: ../../docs/proj1.pdf.

8. Atalhos: links simbólicos e físicos

Às vezes é útil ter um mesmo arquivo (ou diretório) referenciado em vários lugares do sistema de arquivos, sem duplicar seu conteúdo. Para isso existem os atalhos (links), que criam referências indiretas a um arquivo já existente.

9. Sistemas de arquivos populares

Cada sistema operacional tem preferência por determinados sistemas de arquivos, embora vários deles suportem múltiplos formatos:

Sistema de arquivosUsado principalmente em
NTFS (New Technology File System)Windows — suporta permissões avançadas, compressão e criptografia.
FAT / FAT32 / exFATPendrives, cartões de memória, câmeras digitais; sistema mais antigo e simples.
Ext2 / Ext3 / Ext4Linux — Ext4 é o mais usado atualmente, com journaling (registro de alterações) para maior confiabilidade.
HFS+ / APFSmacOS.

Além disso, existem diferentes formas de organizar a estrutura de diretórios em um sistema de arquivos:

  • Diretório de nível único — um único diretório para todos os usuários (usado nos primeiros sistemas de arquivos);
  • Diretório de dois níveis — um diretório separado para cada usuário;
  • Diretório em árvore — a estrutura usada atualmente pela grande maioria dos sistemas (Windows e Linux inclusos), permitindo diretórios dentro de diretórios sem limite prático de profundidade.

  1. O que é um arquivo? Cite pelo menos quatro atributos que ele pode possuir.
  2. Quais são as operações básicas que podem ser realizadas sobre um arquivo? Descreva-as brevemente.
  3. Explique as três formas mais comuns de identificar o tipo de conteúdo de um arquivo (extensão, número mágico, tipo MIME), indicando vantagens e desvantagens de cada uma.
  4. O que é um sistema de arquivos? Qual é o papel do VFS (Virtual File System)?
  5. Explique a principal diferença entre a forma como o Windows e o Linux organizam os volumes de armazenamento (letras de unidade x pontos de montagem).
  6. O que é um diretório, do ponto de vista de implementação? Por que se diz que um diretório "não contém" fisicamente os arquivos?
  7. Explique a diferença entre um caminho de acesso absoluto e um caminho relativo. Dê um exemplo de cada um, no Windows e no Linux.
  8. Explique a diferença entre um link simbólico e um link físico (hard link). O que acontece com cada um se o arquivo original for apagado?
  9. Cite três sistemas de arquivos e o sistema operacional em que cada um é mais usado.
  10. Sobre as afirmações a seguir, indique quais são incorretas, justificando sua resposta:
    1. No Windows, cada volume ou partição recebe obrigatoriamente uma letra de unidade, sem exceção.
    2. Um link simbólico aponta diretamente para o conteúdo do arquivo no disco, e não para um caminho.
    3. No Linux, diferentes volumes (como um disco rígido e um pendrive) podem ser acessados dentro da mesma árvore de diretórios, a partir de pontos de montagem.
    4. Um diretório é, na prática, um tipo especial de arquivo que contém uma tabela de entradas.
    5. A extensão do nome de um arquivo é a única forma possível de identificar seu tipo de conteúdo.
